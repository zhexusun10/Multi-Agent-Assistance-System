# Recommendation interface v2.0

This package contains requests, requirements, the feedback snapshot, evidence, entity-resolution / pool / selection summaries, status/error fields, state/trace references and a generic response envelope. It imports independently of database, agent and recommendation implementation initialization.

`request.py` is the input boundary (`contract_version` `"2.0"`; 1.0 bodies are rejected with `UNSUPPORTED_VERSION`). `feedback.py` defines the complete feedback snapshot sent with every request. `response.RecommendationResponse[T]` is the generic output envelope and `summary.py` its resolution, pool and selection summaries. The concrete item uses internal `ListingSummary` and `ScoreBreakdown` models and is bound in `recommendation.models.candidate.Response`. `limits.py` holds the shared bounds (`MAX_RESULT_LIMIT` = 10, equal to `recommendation.max_result_limit`).

Language-independent consumers should validate against `schemas/request.schema.json` and `schemas/response.schema.json`. All nested definitions resolve inside those documents. Run `python -m recommendation.schemas --check` to detect drift; omit `--check` to regenerate. Generated schemas use the pinned Pydantic 2.14 minor series. The strict TS mirror is `src/contracts/recommendation-native.ts`.

Use a new request ID for each logical update, a stable conversation ID, a complete requirements snapshot, a monotonically increasing requirements version when changed, and the most recent `state.state_id`. Feedback-only requests retain the requirements version. The feedback snapshot is complete every time: `previous_round` (the round the user saw: its request ID, the shown listing IDs and exactly one browsing record per shown ID, `recorded` with seconds or `missing`) and `appointments` (one entry per listing with its counted statuses and action IDs). Nothing is accumulated across requests. `cold_start` carries the orchestrator's exit state. Durations are simulated completed observations, not click counts.

Responses use `success`, `needs_clarification`, `no_match`, or `error`. Only success carries verified recommendations (at most `result_limit`, default 10). There is no unverified-candidate list: listings excluded because a hard criterion is unknown are counted in `pool`. Each item reports its display `rank`, its `score_rank` in the full-pool order and its `selection_reason`. `evidence` holds one entry per (evidence_id, criterion_id) referenced by the returned items. Never treat an error as an empty successful search. `run_sequence` distinguishes feedback-only updates. The orchestrator must discard responses superseded by its latest request.
