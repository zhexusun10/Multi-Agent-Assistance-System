# 推荐工作台页面调整与验收

更新日期：2026-10-21。

## 列表与导航

列表卡片仅展示房源名称、`$1,100 / 月` 格式的租金、匹配条件、合并的待确认项和操作按钮。列表不加载照片，没有卡片折叠条。数据规模和筛选统计由左侧助手回复展示；右侧不再重复展示评估统计、历史快照横幅、房源编号、核验徽章或算法说明。

地点匹配采用推荐结果的 `criterion_results.observed_value`，以米显示实际距离；同一目的地的硬半径和软距离偏好合并展示，保留距离口径与硬上限。未知距离不转换成零。区域距离为零时表达为“位于该区域内”。此处仅做展示转换，不修改推荐状态、证据、分值或排序。

编号导航覆盖所有返回房源，包含待确认候选，编号与卡片一致。点击编号直接定位对应卡片；真实滚动更新高亮。打开详情后返回，保留原来的滚动位置与编号选择。

相关文件：

- `frontend/property-presentation.js`：月租、实际距离、匹配状态和待确认项的共享展示逻辑。
- `frontend/listing-navigator.js`：编号定位与滚动高亮。
- `frontend/app.js`：列表卡片、导航挂载与入口。
- `frontend/index.html`、`frontend/style.css`：列表/导航布局与响应式样式。

## 详情与联系

“展开详情”仍使用完整右侧主区域。详情内的“房源详细资料”统一展示所有已知字段，包括地址、交通、基础属性和挂牌资料。未提供的字段、无意义的卧室零值不生成资料行。照片采用完整等比显示，并随右侧资料实际高度调整相框；小屏自动切换为上下排列。

原来的原始 JSON 证据按钮、更多资料折叠区、黄色设施说明、OSM 采样半径段落、原生评分段落及浏览计时说明均不再渲染。周边地点保留名称、类别、距离和来源链接。

列表和详情统一使用“联系经纪人”。它沿用原看房询问流程，生成 `VIEWING` 草稿；编辑草稿时可选择看房日期和起止时间。保存、复制、自行发送确认、粘贴回复的后续流程保持可用。原始挂牌使用与其他次要操作一致的浅绿边框按钮。

相关文件：`frontend/property-detail-view.js`、`frontend/listing-details.js`、`frontend/followup.js`。后端 `src/domain/explanation.ts`、`src/domain/selection.ts` 只同步入口名称和提示文案，推荐算法及 Agent 路由不变。

## 保留的行为边界

自动浏览记录仍在后台执行。没有新增自动重排触发器；浏览、返回详情、收藏和联系经纪人都不更换当前推荐。只有用户明确重新推荐或修改条件时，才使用符合质量门槛的已有反馈。

## 验收入口

- `tests/property-presentation.test.ts`：实际距离、硬软重复地点、多目的地、区域零距离、未知值与租金失败状态。
- `scripts/test_workbench_presentation.py`：真实南洋理工大学推荐，桌面与390px手机；卡片精简、距离、编号定位/高亮/恢复、动态资料、照片不超出相框、图库、后台浏览记录与列表稳定。
- `scripts/test_browser_interest_followup.py`：合并入口生成 `VIEWING` 草稿，日期时间控件可用，需求和推荐版本不变，没有外部发送。
- `scripts/test_browser_interest_boundaries.py`：聊天/系统说明暂停、真实30秒静默边界、离线持久化和重试。

验收报告：`evaluation/reports/workbench-presentation.json`、`browser-interest-followup.json`、`browser-interest-boundaries.json`。截图：`workbench-list.png`、`workbench-detail.png`、`workbench-detail-bottom.png`、`workbench-mobile-list.png`、`workbench-mobile-detail.png`。
