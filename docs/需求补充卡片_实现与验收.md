# 需求补充卡片实现与验收

## 当前实现

Explanation结果应用成功后，工作流调用Requirement模块下的问题规划器，在左侧对应解释消息中附上卡片引用。问题计划和提交结果保存在PostgreSQL，卡片是聊天历史的一部分。

2026-10-24已将原Mock替换为原生Recommendation 2.0信号：仅当本轮接受的`selection.cold_start.evaluated=true`、`active=true`且仍有适用、未回答/跳过的问题时，提供最多三项的卡片。`active=false`时不追问，已处理的问题不重复；点击“暂不补充”后本会话不再主动提供卡片。阈值与冷启动判断均属于Recommendation，不在应用层复算。

`REQUIREMENT_REFINEMENT_MODE=native`为当前配置，`off`可停止生成新卡片。旧配置的mock值不再强制生成卡片。历史mock卡片仍可读取，新增卡片保存`trigger=native_cold_start`及原始cold_start信号。问题规划、UI、结构校验和提交链路保留，完整说明见[2.0合并与真实需求追问](Recommendation_2.0_合并与真实需求追问.md)。

## 选题

- 基础缺项优先询问预算、卧室数量。
- 房屋类型和挂牌面积要求至少75%的当前展示房源有有效值，并存在可比较差异。面积差异不足50 sqft不主动出题。
- 已有预算但没有价格软偏好时，可以补充理想月租；已有硬距离而没有同目标软偏好时，可以补充更近优先。
- 不主动询问当前原生推荐不能处理的独卫、卫浴数量、真实路线分钟、家具、租期等字段，也不询问产权、每平方英尺租金等次要字段。
- 挂牌面积不代表单独卧室面积；明确单间、主卧/普通房诉求时不主动提面积题。
- 所有选题根据原需求及真实字段判断；未评分房源的占位分数不参与判定，未知不视为失败。

首版没有新增周边地点取证或连续面积/价格utility映射，避免触及Recommendation的内部逻辑。后续可在相关接口和证据接通后扩充问题池。

## UI与提交

- 在解释下方分页展示；上一项、下一项保留选择；最后一页展示本次补充摘要。
- 必须满足和有更好由用户明确选择，不预选答案。不限、暂未想好均不产生相反限制。
- 卡片翻页、填写和状态同步不重新推荐。点击最终按钮后才提交；全部跳过时按钮显示“保留当前推荐”，不启动新任务。
- 未提交草稿按当前用户、会话和卡片保存在当前浏览器localStorage；同一浏览器刷新可恢复，尚未提供跨设备草稿同步。
- 已提交结果由服务器持久化并显示为只读历史；新需求使旧卡片失效，不能用旧表单覆盖新条件。
- 前端直接提交结构化答案，Requirement校验计划归属、字段、比较符、单位、硬软属性和版本后生成现有需求补丁，不调用LLM重新理解表单。
- 表单修改保留未修改旧需求；平方米由代码换算，理想月租不得超过原预算。
- 提交通过持久任务队列运行A→B→C，B接收完整有效需求并正常执行原有推荐。提交幂等、会话隔离、旧版本保护及SSE状态更新均沿用业务基础设施。

## 验收与边界

- Node离线测试：251项通过，21项需显式环境的测试跳过。
- 另显式执行隔离PostgreSQL测试：创建独立schema，完成计划持久化→结构化A→记录样本B→模拟C结果→下一轮耗尽；验证幂等、跨会话、过期、全部跳过及暂不补充。结束清理测试schema，不由生产后台执行测试任务。
- Python同源API测试：8项通过。
- 桌面/手机Playwright：卡片分页、选择保留、错误阻止提交、刷新恢复、轮询不清空输入、提交前右侧不重排、单次结构化提交、新解释、只读历史、手机布局和旧卡失效。
- 构建通过。推荐来源清单仍认可原有71个文件及既有声明补丁，本次没有修改`recommendation/`、原生推荐适配器或原生契约。
- 模型调用为0。数据库流程的Recommendation使用保存的样本评估、Explanation使用模拟结果；浏览器API被测试夹具拦截。本轮没有付费重跑完整原生推荐和LLM解释，正式产品仍继续使用正常的推荐和解释实现。
