# 推荐空排名循环：原因与修复

日期：2026-10-21。

截图中的 `Model turn or time budget exhausted` 是 Recommendation 最终输出与纠错流程的缺陷。已修复并重启本机服务。相同原话现可正常返回四条待确认选项；它们不是已满足全部条件的四条推荐。

## 原始故障

用户输入：

> 你好，我要租裕廊东附近5公里内的房子，预算在2500新币每月，房子附近1公里内最好有MRT或公交站，要求房型为1B1B

原始原生跟踪 `dffc3909-62ac-4603-b8dc-78c7b506d027` 记录了 47.656 秒、8次模型调用、8次工具调用。配置的时间上限为300秒；实际耗尽的是8轮模型调用额度。

1. Requirement 提取出了价格、卧室、卫浴、裕廊东距离和交通软偏好，需求没有因为关键词未命中而被丢掉。
2. 四个原生工具完成检索、地理证据查询、硬条件验证及排序。原生地理接口无法解析 URA 区域目标，全部硬条件可核实的排名为空，正确最终提案应为 `{"listing_ids":[]}`。
3. 模型在 JSON 前添加说明文字。原生控制器按整个字符串解析严格 JSON，第一次输出被拒绝。
4. 纠错时模型将待核实候选编号提交为已通过条件的推荐。原生最终校验正确拒绝了这些编号，因为它们不属于空的已验证排名。
5. 后续重新调用工具耗尽轮数。应用又把内部英文错误原样显示给用户。

原始逐轮输出、工具摘要和错误见 [故障前报告](../evaluation/reports/recommendation-empty-prefix-before.json)。

## 修复位置与边界

| 文件 | 修改 |
|---|---|
| `recommendation/app_controller.py` | 新增应用控制器，继承原生 LiveController；补充输出契约与只读排名状态；将夹有文字或代码围栏的单个、符合原生 Proposal Schema 的 JSON 规范化 |
| `recommendation/app.py` | live 模式使用该应用控制器；显式 scripted 模式维持原实现 |
| `src/domain/errors.ts` | 将推荐服务错误转为简短中文反馈 |
| `src/domain/workflow.ts` | 用户正文使用中文反馈，后台仍保留原生错误和跟踪 |
| `tests/test_recommendation_output_protocol.py` | 原始故障回放、严格提案解析、工具调用不改写、错误编号仍被最终校验拒绝等13项测试 |
| `tests/recommendation-public-errors.test.ts` | 验证用户反馈不泄露内部英文错误 |

控制器明确告诉模型：来源缺失应保持未知，空排名也是已完成的排序，待核实候选由服务另行组装。不能重复检索来“修复”缺失数据，也不能把待核实候选提升为已验证结果。

解析器只接收一个无歧义且符合原生 Schema 的提案，不增加、不删除、不改序任何编号。多个 JSON、非法外层结构或超出原生限制仍由原有有界纠错处理。原始输出与补充的系统提示词、哈希保存在跟踪中，可复查。

没有提高8轮模型、20次工具、2次修复或300秒时间上限，没有引入基线补排。原生四工具、硬条件验证、权重评分、最终重读校验保持原样。上游清单检查通过：71个受保护文件，业务逻辑变更为0。

## 仍未接通的能力

| 条件 | 当前实际状态 |
|---|---|
| 1B1B中的卧室1间 | 传入原生接口并比较 |
| 1B1B中的卫浴1间 | Requirement已提取；原生需求接口尚不支持该字段，应用保留为待确认 |
| 裕廊东5公里 | 已解析为 `URA:AREA:JURONG_EAST`；原生 Place/NEAR_PLACE 查询尚未桥接 URA 区域证据，因此保留为待确认 |
| MRT或公交站1公里软偏好 | 已提取为 PublicTransport；原生当前分类查询没有可用站点证据，因此保留为待确认 |
| 当前是否可租 | 历史房源记录不能证明当前可租，需另行确认 |

以上是原生接口与证据接入边界，不等同于数据库里没有卫浴或系统任何位置都没有交通资料。本次没有擅自丢弃条件、用区域中心点替代区域边界、或更改江山同学的推荐算法。四条待确认选项也不能据此认定在裕廊东附近。

## 验证结果

使用真实配置模型、实际SQL与图谱、完整 Requirement → Recommendation → Explanation 流程创建独立测试会话；没有向任何经纪人发送消息。

| 场景 | 结果 |
|---|---|
| 截图原话：裕廊东5公里、2500新币、交通1公里、1B1B | 正常返回4条待确认选项，0条全部已验证；保留所有条件；原生耗时约19秒，整条流程约34秒 |
| D01、至少5间卧室、每月不超过2000新币 | 正常返回无匹配；没有放宽需求或编造房源 |
| 新加坡国立大学5公里、每月不超过2000新币 | 正常返回已验证推荐，应用列表与原生编号和顺序一致 |

三个场景均为四个工具各执行一次、4次模型调用，原生最终校验通过。真实报告见 [流程回归](../evaluation/reports/recommendation-empty-prefix-workflow.json)。

最初用于无匹配测试的“至少99间卧室”触发了合理的需求澄清；测试改用正常需求表达，没有为通过测试而放松 Requirement 校验。该记录保留在 `evaluation/reports/recommendation-empty-prefix-test-clarification.json`。

桌面1600×1000与手机390×844已检查：四张卡片、条件和待确认项正常显示，联系按钮可见，无横向溢出、内部错误或浏览器异常。见 [页面报告](../evaluation/reports/recommendation-empty-prefix-ui.json)、[桌面截图](../evaluation/reports/recommendation-empty-prefix-desktop.png)、[手机截图](../evaluation/reports/recommendation-empty-prefix-mobile.png)。

源码回归：TypeScript测试189通过、20项按明确配置跳过；Python测试78通过；构建通过。Python有一条现有Starlette/httpx弃用提醒，未造成失败。

此前112条模型样本验证的是 Explanation 模块的表达与忠实度，不覆盖所有推荐字段、地点类型与组合；不能据此称整个系统所有搜索路径已验收。
