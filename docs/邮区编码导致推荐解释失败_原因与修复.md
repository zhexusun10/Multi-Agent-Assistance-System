# 邮区编码导致推荐解释失败：原因与修复

日期：2026-10-22。

## 真实原因

问题原句：

> 帮我找租房，预算不超过5000新币，至少2房，D05

检查最近两次真实请求的任务记录，失败都发生在 Agent C，而不是意图识别、需求提取或 Recommendation。数据库中已保存正确的三个必须条件：月租不超过5000、卧室至少2间、邮区D05。Recommendation 已正常返回房源及逐项结果。

Agent C 的实际错误为：

```text
EXPLANATION_GENERATION_FAILED: GROUNDING: numbers 5 are not supported by this paragraph refs
requirement:monthly-rent,requirement:minimum-bedrooms,requirement:preferred-district
```

旧版校验用 `/\d+(?:\.\d+)?/g` 扫描正文数字，会把 `D05` 拆出数字 `05`，转换成5。事实包中的邮区是字符串，未被加入“可引用的数值”，所以真实的D05被误判为无依据数字。连续三次要求模型重写也不能修正这个代码错误，最终显示通用失败提示。缺少某套房源的资料不应让整个解释失败；本次也不是因为缺资料才失败。

上一轮136条模型样本覆盖了数值型条件、距离、房源楼号和缺资料情形，但漏了含数字的字符串邮区。这是测试覆盖缺口。

## 修复机制

1. **区分数量和标识。** `evidence.ts` 依照现有 `FIELD_RULES` 的字段类型，将字符串和日期保留为完整 `literals`，与 `numbers` 分开。D05、邮编139409、入住日期不是价格或距离，不把它们内部的数字添加到数量许可集合。
2. **逐段精确核对来源。** `validation.ts` 仅在本段引用的事实及其已有关联条件中，允许相同完整字符串；核对后再进行价格、数量和距离校验。不能借用其他段落、其他房源或未引用条件的编码。
3. **错误编码仍拒绝。** D05不会给D06、D050或其他未引用编码放行，编码中的5也不能用来声称月租5新币。六位邮编仍精确校验，不使用数值的四舍五入容差。
4. **日期允许等价表达。** 同一来源日期可以自然写成“2026年12月1日”“2026 年 12 月 1 日”“1 December 2026”等，仍核对完整日期，不将2026、12、1授权为任意房源数量或价格。

LLM继续负责真正给用户展示的正文，保留严格结构输出、引用/数值检查、独立语义复核和有界纠错。本次没有改动推荐算法、原排名或意图识别，也没有以静态字段报告替代解释。

## 这次应如何解释

三个条件必须分开说明：

- **预算：** 所展示记录的月租2500至4500新币，都在5000预算内。
- **邮区：** 所展示记录均为D05。
- **卧室：** 17 Dover Crescent和508 West Coast Drive记录为2间，456 Clementi Avenue 3和511 West Coast Drive记录为3间，这些房源达到至少2间。

NEWest、Lyf One-North Singapore、lyf one-north Singapore 80 Nepal Park和345 Clementi Avenue 5缺少卧室数量资料，不能说已经满足，也不能据此说不满足。它们的租金、邮区记录仍可分别说明符合。

本次没有可用的排序软偏好或浏览兴趣，不能把先后说成越便宜越靠前或第一套最好。当前价格和是否仍可租最后简短提醒即可。

“符合”“明确未达到”“资料不足、还不能确认”是三种不同状态。解释按 Recommendation 实际的 `pass / fail / unknown` 分别表述，不把未知混成未达到，也不因为一个条件未知而省略所有已确认条件。
