# Explanation 3.1：整体比较、灵活介绍与Top 5

## 当前行为

页面每轮合计最多5套，保留Recommendation原排序。正式推荐优先，待核实房源只补足剩余位置，仍保留其必须条件未知的状态；不足5套不编造房源。卡片、数量、编号导航、解释、详情及当前跟进选择共用同一展示范围。原始推荐报文及历史存档保持完整，旧的“5套正式推荐+4套待核实”刷新后也只显示5套；隐藏候选不参与本轮介绍的极值或整体位置比较。

2026-10-24修复的9套问题并非推荐端Top5失效：推荐端原本允许另返4套待核实房源，前端直接把两组拼接成9套。现在`src/shared/recommendation-display.ts`是唯一展示选择器，Node直接使用；前端经`/assets/recommendation-display.js`读取它的编译产物，避免前后端分别截断而出现不同名单。

每套共性的内容是已有月租、房源面积，再按其特点选择卧室、卫生间、房型、楼层、目标地点距离、地铁/公交、超市、食阁、公园及单位面积月租等。叙述顺序和补充角度交给模型；不再要求每套都按价格、面积、地铁排列，也不默认只提一个配套。

## 整体比较事实

`cohort.ts`根据本轮已展示推荐的真实数值生成编辑参考，不计算推荐评分，不改结果次序：

- 最低/最高、并列最低/最高、偏低/中等/偏高；面积对应最小/最大等自然说法。
- 极值先看是否并列；中间位置按同组秩位置区分四分位，不给房源增减权重。
- 组内极差不超过中位数的5%，标为`clustered`，提醒模型不夸大微小差别。
- 极值距中位数至少20%，且距相邻不同值至少10%，标为`stands_out`，允许突出明显差异。例：1500对2300/2400/2600/2700应优先讲本轮最低，而非点名其中一套报差额。
- `complete`标明整组是否都有该字段；缺数据时只允许在有资料的房源中比较。正式推荐与待确认房源分组计算，不把后者混进正式Top5的最优结论。
- 一般介绍不再向模型默认提供逐套邻居差额作为亮点。明确比较两套时仍保留有来源的两两比较；特点确实接近时可少量用差额帮助取舍。

这些阈值属于解释呈现策略，与Recommendation排序公式无关。

## 单位面积月租及自然措辞

每平方英尺月租由同一房源的有效记录月租除以房源面积计算，引用链保留两个原值。单位为新币/平方英尺/月，不能写成元/米。此数值只用于有意义的组内比较，不再作为每套房的普通补充字段单独发给模型。

- 明确记录的租赁范围须一致，不混比整租与单间，不猜测未知口径；月租或面积缺失、为0或与详情冲突时不计算该套比值。
- 同组至少两套有有效比值，并处于高低端、相对中位数偏离至少15%、不属于整体相近的情况，才提供单位面积租金亮点。15%仅是介绍信息的显著程度门槛，不是Recommendation评分参数。
- 中间位置或相近时省略整个话题，改讲其他特点。缺少部分比值时明确只在有资料的房源中比较，不能声称全部五套最低。
- 介绍时同时说明数值、组内位置及实际意义，例如“每平方英尺月租约6新币，在这几套里最高，同样面积要付更多月租，单看空间和月租不太划算”；低的可说“摊下来相对便宜，单看面积和月租更划算”。不强制模型逐字套用例句。
- 没有可比事实时禁止模型自行除算后输出；引用校验要求该套自己的单位面积比较事实。孤立报数、只有高低没有意义，以及错误的元/米单位均触发纠错；独立语义复核继续核对主语、方向、口径及价值判断。不能由此保证整体性价比最高、全部费用最低或卧室面积。

正文可说“附近有X站，资料里写约Y米”，不输出“已收录”“挂牌标注”。OSM测得的距离保留“直线”，房源资料距离不冒充实测、直线或实际步行路线。最近站须有最近站来源字段支持，否则只说附近/资料提及。可以自然介绍多个配套及有限生活意义，不由距离编造分钟、班次或已验证通勤便利。

系统提示词、应用Skill、12条few-shot与独立语义复核同步调整。相近单位租金的示例不再报孤立数值；新增高低两端的意义表达示例。严格JSON、原顺序、核心信息、补充信息、引用来源、数值及路线边界继续校验；文案依然由LLM生成。

## Top 5接口调整

应用请求本来就是5，但旧适配器截为4，Python请求、响应、rank和模型Proposal也限制4。本次统一改为5，同时更新Python与TypeScript校验和生成Schema。工具仍是原四个工具，工具预览条数不等于最终推荐条数；排名、度量、硬过滤、特征屏蔽、权重和工具计算核心保持原字节。声明的下游补丁保留原上游指纹，便于队友比对。
