# NUS需求更新后解释失败：原因与修复

2026-10-22。问题原句：“地址离nus越近越好，然后1个房间”。

## 归因

实际失败任务为Agent C，错误类型是 `EXPLANATION_GENERATION_FAILED: SEMANTIC_AUDIT`。本次不是402余额错误，也不是需求未提取或没有推荐结果。需求已更新为1间卧室、预算5000、D05，保留超市800米偏好，并新增NUS更近优先。

原解释/复核上下文没有明确区分三件事：某项资料是否已知、能否比较这项事实、该房源是否参加本轮入选排名。复核因此拿补充展示的345 Clementi Avenue 5的超市距离约57米，质疑排名第一的441B约60米；但前者缺卧室资料，没有参加这组排名。复核还错误要求将第一套较低租金作为排序原因，实际预算只是硬条件，真正生效的是学校和超市两项距离偏好。

多偏好下，441B到学校约2517米、到超市约60米；449到学校约2370米、到超市约140米。前者超市项更有利，后者学校项更有利，原生推荐综合后441B排前。第一名不需要每项都最近。实际贡献方向直接读取原返回，没有重新计算或调整权重。

## 修改

- 解释事实包明确列出入选排名范围、仅作筛选的条件、未进入排名的补充房源，以及逐项贡献的取舍方向。
- 增加逐条件缺资料清单。缺卧室的四套中，只有其中三套也缺学校/超市距离；不能合并成“四套都没有距离资料”。345的学校、超市距离继续如实保留。
- 更新生成提示词、独立复核契约和对应示例，要求分别判断资料状态和排名资格，不凭低租金追加排序因素。
- “更近优先”标明为无距离上限的相对偏好。页面显示真实距离和方向箭头，不把内部1000米评分尺度显示成红叉；用户明确的距离上限仍保留通过/未达到状态。
- 压缩模型上下文：后台仍保存全部来源、数值许可和原始引用；模型使用可逆短引用，保留全部需求观察值，仅发送相关两两比较。此案例事实包由56999字符压缩为13923字符，纠错不再重复发送完整事实包。字符减少不等同于精确token或金额节省比例。

Recommendation原生业务逻辑、评分、权重、排序，以及其他Agent未修改。71个受保护文件检查的业务变更数为0。

## 验证范围与费用

- 离线TypeScript测试：216通过，20个需外部服务/显式开启的测试跳过；构建通过。
- 针对本次真实数据的测试覆盖：未入选但距离已知、预算不奖励排名、双距离取舍、按条件分别列缺失信息、短引用往返及错误数字仍被拒绝、偏好红叉修正。
- 本次总共3次付费请求：第一轮生成及独立复核2次，暴露缺资料分组错误后本地修正；最后仅追加1次正文生成，真实正文通过本地结构/引用/数值检查，并逐项对照原始数据审阅。未追加付费评分，没有重跑Requirement、Recommendation或网页提问。
- 用保存数据单独渲染前端匹配组件，确认2517米的更近偏好显示为方向箭头、没有红叉；此检查没有提交聊天或模型请求。
- **最终版独立模型复核和完整线上对话链路未再付费重跑。** 不能把最后一次仅正文验证说成完整流程已全部通过。原先失败及此次调用记录均保留：`evaluation/reports/explanation-update-live-before-coverage.json`、`explanation-update-live.json`、`explanation-update-offline.json`。

当前服务已重启加载修改。用户原失败消息作为历史记录保留，未直接改写为新回答。
