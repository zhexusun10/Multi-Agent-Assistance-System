# Explanation：恢复自然介绍并消除重复距离

2026-10-24。保持用户确定的逐套选房顾问角色：说明月租、面积在本轮的位置，补充交通和生活配套，结合房源特点灵活组织口语化的取舍建议。名单、次序和推荐算法不变。

## 原因

用户的 NUS 3 公里和 Clementi MRT 案例，保存的生成记录均显示 `evidence_recovery`。正常模型介绍未通过复核，多轮重写后切到了程序备用文案。备用文案依次拼价格、面积、逐项距离，再取一个额外字段，导致表达变成字段串，并常常选择了建成年份而没有保留丰富的周边配套。同一地点的硬半径和更近优先各有条件结果，备用循环把同一观测值写了两遍。

复核记录也暴露出误判：把并列最近的合理说法判错；把指定目的地距离的本组比较与“最近地铁站”混淆；因软偏好标记为 fail 而否认有效距离的相对远近；把详情有卫浴记录与推荐条件仍未验证判为矛盾；把可选建议、正确陈述甚至复核员自己读错的年份当作必须纠错。真实错误仍然存在，因此保留独立复核与确定性校验。

## 修改

- 写作契约、系统提示词、应用 Skill 和复核提示词同步明确：正常介绍由模型生成，数据与取舍连起来，各套可从不同亮点起笔，可介绍多个具名配套，不回到固定字段清单。修饰语必须有来源，不承诺实际路线、舒适度或独卫。
- 在同一个已展示推荐组内，按目的地、距离口径、交通方式和单位生成距离整体比较事实，保留来源链、并列和完整性。硬半径与更近优先共享一次观测；不同目的地、不同口径或相冲突数值不合并。区域内的零米是真实距离，可参加比较；零租金或零面积仍不当事实。
- 同一地点、同一口径、同一个观测值在备用介绍里只说一次，同时引用两项条件。备用介绍也整合月租/面积取舍，优先保留多个交通、采购、用餐等信息，不再只取第一个建成年份字段。后台仍明确标记备用模式和未执行模型复核，不能冒称正常模型结果。
- 明确复核边界：允许正确的整体比较、有限的日常选房建议，以及“详情有记录、推荐条件仍需核实”的分层说明。仅有可选措辞建议时应通过，事实错误仍须拒绝。
- 补充确定性检查：建成年份必须精确对应本套引用，不使用距离的数值近似容差；面积和距离居中、月租最高时，不得一句“这些都居中”混写。后续修复由正常模型纠错机制执行。

## 验证与费用

两个实际案例已保存为脱敏回归样本，覆盖重复距离、不同地点、别名、未知条件、冲突观测、中英文、区域零米、并列距离、卫浴记录分层、多种配套、精确年份及不同字段的整体位置。测试不调用模型，原始需求与推荐结果、次序保持不变。

真实验证仅复用一次已保存的 Clementi MRT 推荐，未重新执行需求提取或推荐。生成与独立复核共 **2 次模型请求**，SDK 自动重试关闭。模型恢复了自然介绍并通过当次复核。随后来源核对发现一句把月租也概括成“居中”的错误，已按既有比较事实改为面积和距离居中、月租并列最高，并通过本地校验；未追加模型调用。该原文、修正文及来源检查都已存档，生成元数据明确标为 `not_rerun_after_source_correction`，不声称修正文再次通过模型复核。

当前案例仅替换最新的备用介绍消息，不修改用户历史提问、原推荐报文、房源次序或需求。修复有当前操作、请求 ID、活动任务和最新消息匹配保护。其他历史消息保留原样。

NUS 会话当前介绍也已恢复：使用该次操作已保存的模型文稿作为待核对文字，按当时的引用映射还原引用，逐项对照接受的推荐与补充资料，修正卫浴使用安排措辞，再执行现行校验。没有把失败文稿当作事实来源，也没有重新推荐或调用模型。原备用介绍及修复结果已存档，元数据为 `saved_llm_source_checked`、`semantic_audit=not_rerun`；此为本次有来源核对的维护操作，不是产品自动放行失败稿件的机制。
