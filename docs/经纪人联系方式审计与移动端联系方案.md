核查日期：2026-10-20。范围为本地历史 CSV 样本，不能外推为新加坡经纪人整体的渠道或设备使用比例。

房源电话字段为 `agent_phone`。200 条有电话房源去重后对应 162 个号码。全部符合 `65` 国家代码加新加坡移动号码的格式模式，没有进行号码当前活跃性或运营商核验。

经纪人导出表保存了 162 位经纪人，`phone` 均非空，且号码互不重复。这表示这张经纪人表中电话覆盖率为 100%，不表示全部 593 条房源的所有经纪人都已采集：房源记录中出现了未进入该经纪人表的其他执照号。

## 已发现的可改进点

按 CEA 执照号对两份主文件做严格关联，且关联结果只有一个号码时：

- 全部房源可额外找回 32 条电话，覆盖从 200/593 提升至 232/593，39.12%。
- 租赁房源可额外找回 29 条电话，覆盖从 100/475 提升至 129/475，27.16%。
- 出售房源可额外找回 3 条电话，覆盖从 100/118 提升至 103/118，87.29%。
- 当前样本中未发现这一关联的电话冲突或一个执照关联多个不同号码的情况。

这只是只读补全计算。现有联系人线索接口仍只查询房源行上的 `agent_phone`，尚未增加该关联补全。号码补全不能转化成 WhatsApp 已开通证明。

后续数据契约应将电话与渠道证据分开保存。优先请数据同学检查同一历史快照是否保留原始联系人类型或 WhatsApp 链接；没有证据时 UI 显示“尝试通过 WhatsApp 联系，渠道未核实”，不能显示“已验证 WhatsApp”。

## 手机与电脑的联系流程

WhatsApp 官方说明 Click to Chat 可在手机和 WhatsApp Web 使用，并支持预填文本：

<https://faq.whatsapp.com/5913398998672934>

| 用户设备 | 预期流程 |
| --- | --- |
| 手机浏览器访问本项目网页 | 点击官方链接，按系统提示打开已安装的 WhatsApp，预填草稿，用户检查后发送 |
| 电脑浏览器访问本项目网页 | 打开 WhatsApp 官方跳转页，再使用已登录的 WhatsApp Web，或按系统选择桌面客户端；未登录需先关联账号 |
| 电脑选房、手机发送 | 工作台可新增同一聊天链接的二维码；手机扫码后打开 WhatsApp，需单独实现，电脑点击链接不会自动远程打开手机 |

需要用户设备上的 WhatsApp 账号登录。不需要把用户 WhatsApp 密码、验证码或登录会话交给我们的服务器。

跳转可能出现“继续聊天”或“打开应用”确认，不应承诺零次确认或每一种内置浏览器都可直接打开。长文本应有复制草稿作为备用方案。跳转及预填不等于发送，不提供送达或回复数据。

## 网页发布与原生 App

推荐先做手机友好的响应式网页。手机通过浏览器打开可访问网址，就能使用上述流程，不需要先打包 APK/IPA 或上架商店。

如需桌面图标或接近独立应用的打开方式，可进一步实现 PWA 或添加到主屏幕。通过浏览器安装 PWA 不要求先创建应用安装包，具体安装能力因浏览器和系统而异：

<https://web.dev/learn/pwa/installation>

如果以后选择上架原生或包装后的 App，再承担对应打包、签名、商店资料和审核流程；这不是当前 WhatsApp 跳转的前置条件。

现有前端已经设置 viewport，并有 850px 以下单列布局。这只能说明已有基础窄屏样式，未完成本次真实手机端到端验收。Click to Chat 和二维码按钮尚未加入。

当前启动脚本将网页监听在 `127.0.0.1`。手机访问 `127.0.0.1:8010` 指向手机自己，不能访问电脑上的应用。移动端使用之前，需要配置手机可达的测试地址或部署 HTTPS 网站；不能只把网址里的 IP 改成电脑 IP，却保留服务只监听回环地址。部署时继续保留用户鉴权，不直接开放 PostgreSQL、Neo4j 或内部数据服务。

## 产品建议

以手机作为重要使用场景，兼容电脑。当前数据没有终端使用调查，不能给出“手机占多少、电脑占多少”的统计结论。

优先实现“网页选房、审核草稿、打开 WhatsApp、用户发送、返回录入回复”的流程。需要电脑选房后转手机时，再增加二维码交接。是否打包原生 App 与能否调用 WhatsApp 官方聊天链接无关。

## PropertyGuru 原页面联系作为号码缺失的兜底

追加核查日期：2026-10-20。

官方新加坡经纪人帮助中心说明，新的 WhatsApp enquiry flow 从 2026-10-01 起逐步上线：用户选择 WhatsApp 咨询，首次输入并通过 OTP 验证自己的手机号，平台在验证后向经纪人交付询盘，再把用户带到经纪人的 WhatsApp。后续询盘在用户确认继续到 WhatsApp 时交付线索，再完成跳转。由于分批推出，实际页面可能仍采用旧流程。

官方来源：<https://www.agentofferings.propertyguru.com.sg/help-centre/manage-your-leads/new-whatsapp-enquiry-flow/new-whatsapp-enquiry-flow/>

因此，没有采集到经纪人电话不代表用户没有联系入口；在原房源仍可访问且允许咨询的前提下，可以通过原站流程联系。但 593 条历史链接不证明 593 套房源当前仍可联系。

实现建议：工作台新增“复制咨询草稿”和“前往 PropertyGuru 联系”两个按钮。草稿保留在本系统，用户到原站按实际页面完成个人登录、手机号验证及咨询；不能声称我们的跳转能自动预填 PropertyGuru 表单，或已经替用户完成发送。用户返回后手动记录提交结果及录入回复，继续沿用看房、提醒和总结流程。

本次官方公开资料检索未找到供一般第三方开发者代租客提交询盘、向任意经纪人发送消息并读取回复的公开 API 文档；这不等于断言不存在商业合作接口。房源/市场数据读取、询盘写入、消息回复读取是三个不同能力，需分别取得官方文档、账号权限和使用范围后才能承诺接入。页面内部请求或第三方抓取包装 API 不能自动视为 PropertyGuru 官方开放接口。

PropertyGuru 的 Acceptable Use Policy 对未经授权的自动访问、抓取和采集作出限制，因此当前方案不以模拟登录并调用私有接口作为稳定集成路径：<https://www.propertyguru.com.sg/customer-service/acceptable-use>

本节仅为接入方案与公开资料核查，未新增网站自动采集、未提交任何询盘，也未改动固定房源快照。
