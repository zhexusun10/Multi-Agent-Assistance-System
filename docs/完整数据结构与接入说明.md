## 数量与关联

| 表 | 行数 | 作用 |
| --- | ---: | --- |
| properties | 21,431 | 房源主体；全部为 RENT，currency 全部为 SGD，覆盖 D01–D28 |
| agents | 4,657 | 已收录的经纪人独立资料 |
| property_images | 418,700 | 房源图片 URL、类型、来源页和展示顺序 |
| price_history | 0 | 保留成交历史表结构，本快照没有记录 |

`properties.listing_id` 是原生 PropertyGuru 房源 ID；不是系统生成的推荐序号。`property_images.listing_id` 外键指向房源，删除策略为 CASCADE；图片唯一键为 `(listing_id, source_page, image_url)`。

`properties.agent_id` 是逻辑关联字段，没有数据库外键：本快照房源共引用 **8,028** 个不同 ID，其中 **3,371** 个在独立 `agents` 表没有对应行。图谱保留这些房源中的经纪人 ID 关联，所以 Neo4j Agent 节点有8,028个；不能把它们等同为4,657条完整经纪人资料，也不能据节点存在就推断联系方式完整。Project 节点从房源 project_id 建立；原 SQLite 没有单独 projects 表。`price_history.project_id` 也没有数据库外键。

迁移沿用团队导入器：保留业务主键、字段及 JSON；图片内部自增ID由目标库生成，跨库比较图片应使用上述复合唯一键。PostgreSQL 的创建/更新时间会记录导入/更新操作；原始记录时间仍保留在只读 SQLite 中，不能把导入时间当作房源当前可租的核验时间。

## 房源字段分组

- 标识与类型：listing_id、listing_type、transaction_category、title、property_type、project_id。
- 价格：price、currency、price_type、psf。
- 户型与面积：bedrooms、bathrooms、floor_area_sqft、land_area_sqft。
- 建筑产权：tenure、tenure_category、build_year；tenure 是物业产权，不等于租客最短租期。
- 地址与位置：full_address、short_address、district_code/text、region_code/text、postal_code、street_name/number、block、unit、floor_level、latitude、longitude。
- 交通：nearest_mrt、mrt_distance_m、mrt_walking_mins；挂牌标注与自行计算的直线距离分别保留，不能当作已验证通勤路线。
- 经纪人与公司：agent_*、agency_id、agency_name；电话线索不会直接进入公共图谱或大模型。
- 媒体与原文：url、thumbnail_url、homepage_images、detail_images、price_insights、raw_json。
- 状态与时间：is_verified、is_official、detail_fetched、posted_at、created_at、updated_at；历史挂牌标志不代表本平台已核实当前可租。

## JSON 和图片结构

SQLite 四个 JSON 列在 PostgreSQL 中为 JSONB：

```text
homepage_images（21,431条为对象）
├── thumbnail
├── preview_images[]
└── preview_count

detail_images（8,634条为对象）
├── photos[]
├── floor_plans[]
├── photo_count
└── floor_plan_count

price_insights（1,558条为对象）
├── srpSimilarListingUrl
└── shouldHidePriceHistoryComparison

raw_json（21,431条为对象）
└── 原始页面结构，例如 property、price、bedrooms、bathrooms、mrt、
    listingFeatures、agent、mediaItems、availabilityInfo 等
```

JSON keys 是按实物抽样审计的常见结构，不能保证每条都含全部 key。`raw_json` 只保留原始证据，不作为未经验证的可执行条件，也不直接暴露给前端/模型。

图片表记录数：HOMEPAGE/THUMBNAIL 21,431；HOMEPAGE/PREVIEW 298,345；DETAIL_PAGE/PHOTO 97,172；DETAIL_PAGE/FLOOR_PLAN 1,752。总计418,700条记录，跨来源去重后有238,308个不同 image_url。同图可能同时出现在缩略图和预览中，这是来源记录，不等于418,700张不同照片。这里保存的是外部图片链接，未把图片二进制下载到本机；界面按已收录链接加载，远端失效时显示加载提示。

## 推荐查询与验收

full 模式通过新增只读 `/api/v1/listings/assessment/search`，每页最多1,000条按主键扫描全部21,431套。字段来自 SQL 白名单，保留 NULL，不提前丢弃未知硬条件；每页保存来源引用，校验游标不重复、房源ID不重复、总数与快照声明一致。达到资源边界会报错，不会把截断扫描当作完整覆盖。

本地 baseline 对全部记录评估硬条件，再对各组按明确软偏好排序；详细空间证据只为展示结果和放宽建议保存，避免对2万多条逐个调用详情或逐个写入空间证明。远程队友 Recommendation Agent 接口仍可替换，当前没有把本地基线冒称为队友实现。

实际 DeepSeek + 网页接口 + SQL 独立公式验收：

- D05、至少2房、月租≤5,000：全部评估21,431套，通过161、未知6、排除21,264；返回顺序与独立SQL结果一致。
- NUS 3公里、最近MRT 3公里、月租≤3,000、独立卫浴：待核实4,193，排除17,238；前五套距离与独立球面余弦计算一致；没有把独立卫浴未知标为通过。
- 去掉独立卫浴：通过246、待核实3,947、排除17,238；未知大多来自缺少坐标，分别展示。
- 选中新快照候选后可创建看房草稿及总结；抽查房源照片6张、周边地点97个。
- SQL/Neo4j逐条字段与关系校验通过，HTTP分页实际读到21,431条；未知坐标、照片分页、数据源一致性均通过。
- 浏览器验证完整快照提示、资料照片、折叠、手机布局和旧会话提示，结果见 full-data-ui.json。
